# Kavach Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deployed Next.js app where a woman registers real photos, drops a morphed image, gets a derivation verdict with a blurred stamped exhibit, and downloads Gemma-drafted platform and cyber-crime complaints.

**Architecture:** Next.js 15 App Router on Vercel. All images go through our API routes into Cloudinary `type: private`; the client never gets a bare Cloudinary URL. Fingerprints are Cloudinary `phash` plus our own pHash/dHash on the `g_face` crop (sharp). Profiles and cases are JSON raw assets in Cloudinary, so there is no database. Gemma 4 (Gemini API) drafts complaints from blurred derivatives and structured evidence; Claude is a fallback behind `LLM_PROVIDER`.

**Tech Stack:** Next.js 15, React 19, TypeScript strict, Tailwind v4, `cloudinary` v2, `sharp`, `@google/genai`, `@anthropic-ai/sdk`, `vitest`, Vercel CLI.

**Spec:** `docs/superpowers/specs/2026-10-23-kavach-design.md`

## Global Constraints

- The suspect ("exhibit") image is never rendered, logged or sent to an LLM unblurred. Only `e_pixelate_faces,e_blur:600` derivatives with the stamp leave Cloudinary, via signed, expiring access.
- All Cloudinary uploads use `type: "private"` under `kavach/<profileId>/{vault|exhibits|cases}/`.
- Gemma receives only blurred derivatives and structured evidence; victim name and post URL are replaced by `[VICTIM_NAME]` and `[POST_URL]` before the call and restored after.
- Default model `gemma-4-26b-a4b-it`, fallback `gemma-4-31b-it`, Claude fallback `claude-haiku-5-5`. `LLM_PROVIDER` is `gemma|claude|demo`, default `gemma`.
- Similarity thresholds: `>= 0.80` derived, `0.60..0.80` likely, `< 0.60` none.
- Upload cap 4 MB; client downscales to max 2048 px edge before upload.
- `DEMO_MODE=1` or missing `CLOUDINARY_URL` means demo mode: seeded profile "Priya", uploads disabled, banner shown.
- Copy voice: calm, fierce guardian. Second person, short sentences, no exclamation marks. Every complaint draft ends with "Verify section numbers with the portal or a lawyer before filing."
- MIT licence. Spend under 25 USD.

## Review Focus

1. A suspect image with no detectable face (screenshot with the face cropped tiny, or a non-face image): match must fall back to full-image hashes and the case page must still render. Test in Task 3 (`bestMatch` with no face fingerprints).
2. A mirrored or recoloured derivative: must still score `derived`. Test in Task 2 (mirror and tint variants) and Task 3.
3. Wrong PIN or someone else's case id: must be refused, not leak case data. Test in Task 4 (session) and Task 7 (case route returns 404 for other profile).
4. Gemma returns prose or fenced JSON instead of clean JSON: parser must recover or fall back to demo text with a banner. Test in Task 8 (`parseDraft`).
5. Non-image or oversized upload: route returns 400 with a plain message, nothing stored. Test in Task 7.

### Task 2: Fingerprints

**Files:**
- Create: `src/lib/fingerprint.ts`, `tests/fingerprint.test.ts`

**Interfaces:**
- Produces:
  - `type Fingerprint = { phash: string; dhash: string }` (16-char hex each, 64 bits)
  - `fingerprint(buf: Buffer): Promise<Fingerprint>`

  - `similarity(a: string, b: string): number` = `1 - hamming/64`
  - `mirror(buf: Buffer): Promise<Buffer>` (horizontal flip via sharp)
  - `faceCrop(buf: Buffer, box: {x:number;y:number;width:number;height:number}): Promise<Buffer>` (crop with 20% padding, clamped)

```ts

test("different image is far", ...)      // similarity(base, noise) <= 0.6 on phash
test("mirror then mirror matches", ...)  // fingerprint(mirror(mirror(base))) phash equals base phash
```

### Task 3: Matching

**Files:**
- Create: `src/lib/match.ts`, `tests/match.test.ts`

**Interfaces:**
- Consumes: `Fingerprint`, `similarity` from Task 2.
- Produces:
  - `type PhotoPrints = { cldPhash?: string; full: Fingerprint; fullMirror: Fingerprint; face?: Fingerprint; faceMirror?: Fingerprint }`
  - `type Verdict = "derived" | "likely" | "none"`
  - `type MatchScore = { score: number; parts: Record<string, number>; mirrored: boolean }`
  - `scorePair(suspect: PhotoPrints, candidate: PhotoPrints): MatchScore`
  - `type MatchResult = { verdict: Verdict; score: number; bestIndex: number; parts: Record<string, number>; mirrored: boolean; methods: string[] }`
  - `bestMatch(suspect: PhotoPrints, vault: PhotoPrints[]): MatchResult` (empty vault returns `none`, `bestIndex: -1`)
  - `THRESHOLDS = { derived: 0.80, likely: 0.60 }`

Scoring: with face prints on both sides, `0.40*cldPhash + 0.35*face.phash + 0.25*face.dhash`; without, `0.60*full.phash + 0.40*full.dhash`. `cldPhash` term uses `full.phash` when either side lacks `cldPhash`. Compute once with the suspect's normal prints and once with its mirror prints (mirror prints compare against the candidate's normal prints), take the higher, set `mirrored`. `methods` lists the names used, e.g. `["cloudinary-phash","face-phash","face-dhash"]`.

- [ ] **Step 1: Write the failing tests** using hand-made hex strings (no images): identical prints score 1 and `derived`; prints differing in 20 of 64 bits on every hash score about 0.69 and `likely`; 40 bits differing scores `none`; a suspect whose mirror prints match the candidate exactly returns `mirrored: true` and `derived`; no face on suspect uses the full-image formula and `methods` has no face entries; empty vault returns `none` with `bestIndex -1`.
